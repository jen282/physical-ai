# TeachArm 엣지 vs 클라우드 비교 보고서

- 대상 서비스: TeachArm – 시연으로 가르치는 모방학습 로봇팔
- 작성일: 2026-10-07
- 결론: **엣지 방식 채택** (5개 기준 모두 엣지 우세)
- 근거 문서: `PRD/PRD_arm.md` (※ 표시된 수치는 PRD에 없어 이 보고서에서 둔 가정)

---

## 1. 한 줄 요약

> 로봇팔은 30Hz로 계속 움직여야 하고, 현장 인터넷은 보장되지 않으며, 작업 영상에는 공정 정보가 담기고, 모델은 노트북·Pi 5에서 돌릴 수 있는 크기다.
> 그래서 **엣지가 맞고**, 클라우드는 팔이 움직이는 도중 통신이 흔들리면 **제어 품질이 직접 떨어진다.** 비용도 5년 기준 엣지가 약 40배 저렴하다.

---

## 2. 서비스 개요

사람이 리더 팔로 시연을 수십 번 보여주면, 로봇이 모방학습(ACT) 정책을 학습해 큐브를 집어 접시 위에 놓는 작업을 스스로 수행하는 서비스입니다. 실행 중에는 두 카메라 영상과 관절 상태를 입력받아 관절 목표값 묶음(Action Chunk)을 계속 출력합니다.

| 축                  | 주어진 자료                                                                                                |
| ------------------- | ---------------------------------------------------------------------------------------------------------- |
| 속도                | 제어 루프 30Hz(주기 약 33ms), 제어 주기 지연 p95 40ms 이내, 노트북 추론 p95 50ms·Pi 5 p95 300ms 목표      |
| 비용                | 셀 3개 기준 팔로워 팔 3대, 상단·손목 카메라 셀당 2대(총 6대), 640×480 30fps 영상                           |
| 예상 비용(엣지)     | Raspberry Pi 5 3대 × 200,000원 = 60만 원(1회) + 유지보수 연 20만 원(※ 가정)                               |
| 예상 비용(클라우드) | 추론 GPU 서버 연 1,000만 원 + 영상 업로드 회선 연 120만 원 + 영상 저장 연 200만 원(※ 모두 가정)           |
| 오프라인            | 평가 서버는 로컬 LAN 전용이며, 현장 인터넷 연결은 보장되지 않음. PRD는 클라우드 실시간 추론을 범위에서 제외 |
| 프라이버시          | 개인정보는 없으나, 확장 단계에서는 현장 부품·공정 영상이 노출됨                                            |
| 모델 크기           | ACT(ResNet18 + Transformer + CVAE) 수십~100M 파라미터급, 체크포인트 약 수백 MB(※ 실제 크기 확인 필요)      |

## 4. 기준별 비교 분석

### 4.1 속도 → 엣지 우세

- 제어 루프가 30Hz이므로 한 스텝은 **약 33ms**이고, 제어 주기 지연은 p95 **40ms 이내**를 유지해야 합니다. 팔이 큐브를 잡으러 움직이는 동안 명령이 끊기면 동작이 멈칫하거나 파지 타이밍을 놓칩니다.
- **엣지**: 카메라 → 같은 책상의 노트북 또는 Pi 5 → 추론 → 서보. 유선 USB와 로컬 장치만 거치므로 지연이 짧고 일정합니다.
  - 목표는 노트북 p95 50ms, Pi 5 p95 300ms입니다. Pi 5는 한 번의 추론이 느리지만, ACT는 한 번에 수십 스텝 분량(Action Chunk)을 출력하므로 **추론 간격이 길어도 동작이 이어집니다.** 다만 Pi 5의 실제 지연과 성공률은 실험 ④에서 측정해야 확인됩니다.
- **클라우드**: 촬영 → 인코딩 → 인터넷 업로드 → 서버 대기열 → 추론 → 결과 회신 → 서보. 단계마다 지연이 붙고, 인터넷 구간은 지연이 들쭉날쭉(지터)합니다.
  - Action Chunk 덕분에 평균 지연은 어느 정도 흡수할 수 있어 "불가능"까지는 아닙니다. 그러나 **지연이 튀는 순간에는 최신 영상 대신 오래된 영상 기준의 행동**이 실행되어, 파지처럼 정밀한 구간에서 실패로 이어집니다. PRD도 "네트워크 지연이 제어 품질에 직접 영향을 준다"며 클라우드 실시간 추론을 범위에서 제외했습니다.

### 4.2 비용 → 엣지 우세

**연간 비용 구조** (※ 엣지·클라우드 운영비는 모두 가정치)

| 항목        | 엣지                    | 클라우드                                                                   |
| ----------- | ----------------------- | -------------------------------------------------------------------------- |
| 초기 비용   | 60만 원 (Pi 5 3대)      | 0원                                                                        |
| 연간 운영비 | 20만 원 (유지보수·교체) | 1,320만 원 (GPU 서버 1,000 + 회선 120 + 저장 200, 3셀이 서버 1대를 공유 가정) |

연간 운영비만 놓고 보면 클라우드(1,320만 원)가 엣지(20만 원)의 **약 66배**입니다. 클라우드는 GPU 서버를 상시 켜두는 비용이 대부분을 차지합니다.

**누적 비용 비교**

| 기간 | 엣지     | 클라우드    | 차이                       |
| ---- | -------- | ----------- | -------------------------- |
| 1년  | 80만 원  | 1,320만 원  | 1,240만 원                 |
| 3년  | 120만 원 | 3,960만 원  | 3,840만 원                 |
| 5년  | 160만 원 | 6,600만 원  | **6,440만 원 (약 41배)**   |

- **손익분기점: 약 0.6개월.** 클라우드는 한 달에 약 110만 원씩 나가므로, 엣지의 초기 투자 60만 원은 1개월이 안 돼 회수됩니다.
- 클라우드 비용의 대부분은 **영상을 계속 올리고, 계속 추론하고, 계속 저장하는 데서** 나옵니다.
  - 카메라 2대 영상을 H.264로 압축하면 셀당 약 2Mbps(※ 가정), 3셀이면 **약 6Mbps**를 가동 시간 내내 올려야 합니다. 압축하지 않은 원본(640×480×3byte×30fps)은 카메라 1대당 약 221Mbps라 사실상 압축이 필수입니다.
  - 하루 8시간 가동(※ 가정)이면 약 **22GB/일, 연 약 5.4TB**(250일 기준)가 쌓입니다.
  - 셀을 늘리면 회선·서버·저장 비용이 함께 늘어나는 구조입니다.
- 엣지는 초기 비용 이후 거의 고정 지출이라 예산 예측이 쉽습니다. Pi 5를 5년 뒤 전부 재구매(60만 원)해도 클라우드 1년 비용보다 훨씬 적습니다.

> 참고: 학습은 엣지·클라우드 구분 없이 **Colab GPU(월 약 7만 원)** 에서 수행하며, 이는 PRD 운영비에 이미 포함되어 있어 위 비교에서는 제외했습니다. 비교 대상은 "학습이 끝난 정책을 실행(추론)하는 곳"입니다.

### 4.3 인터넷 사용(오프라인) → 엣지 우세

- 시스템의 모든 통신이 **USB(서보·카메라)와 로컬 LAN(평가 서버)** 으로 설계되어 있고, 평가 서버도 인증 없이 로컬 네트워크에서만 접근합니다.
- **엣지**: 모든 처리가 책상 위 장치 안에서 끝나므로 인터넷이 끊겨도 작업이 계속됩니다. 기록 데이터는 로컬에 쌓아두었다가 나중에 보내면 됩니다.
- **클라우드**: 인터넷이 끊기는 순간 정책 출력이 멈춥니다. 팔이 큐브를 쥔 채로 멈추거나, 30초 타임아웃으로 홈 복귀하며 시도가 실패 처리됩니다. 현장에서 외부 연결이 제한된 경우에는 보안 예외와 별도 회선까지 필요합니다.

### 4.4 프라이버시 → 엣지 우세

- MVP의 큐브·접시 영상은 민감하지 않지만, 확장 단계(부품 키팅 파일럿)에서는 영상에 **현장 부품과 공정 방식이 그대로 찍힙니다.** 개인정보는 없어도 평가 기준상 "중요한 데이터"에 해당할 수 있습니다.
- **엣지**: 영상이 책상 위 장치와 사내 로컬 서버 밖으로 나가지 않습니다.
- **클라우드**: 작업 영상이 ① 인터넷 구간을 타고 전송되고 ② 외부 서버에 저장됩니다. 시연 데이터는 곧 작업 노하우이므로 유출 시 되돌릴 수 없습니다.
- MVP 단계에서만 보면 차이가 크지 않아 클라우드를 △로 평가했습니다.

### 4.5 ⭐ 모델 크기 → 엣지 우세

- ACT는 ResNet18 비전 인코더 + Transformer + CVAE 구성의 **수십~100M 파라미터급 모델**로, 대규모 사전학습 모델(VLA 등)에 비하면 작습니다. (정확한 크기는 학습된 체크포인트로 확인 필요)
- 평가 기준의 "작은 모델 = 엣지"에 해당합니다. 노트북(GPU)에서는 문제없이 돌아가고, Pi 5(CPU)는 **ONNX 변환과 입력 해상도 축소**로 최적화해 실험 ④에서 가능 여부를 검증합니다.
- 클라우드의 장점인 "엣지에 안 들어가는 큰 모델도 돌릴 수 있다"는 이 서비스에서는 필요하지 않습니다. 언어 명령 기반 VLA 모델은 PRD에서 범위 밖으로 둔 항목이며, 이를 도입하게 되면 이 기준은 재평가해야 합니다.

| 장치 고장                 | 해당 셀 작업 중단                             | 예비 Pi 5 보유, 안전 계층(비상정지·토크 제한)은 AI와 독립 유지    |

## 7. 최종 결론

**TeachArm은 엣지 방식으로 구축합니다.** 학습은 Colab에서, 실행(추론)은 로컬 장치에서 하는 구성입니다.

1. **속도**: 네트워크를 거치지 않아 30Hz 제어 루프를 안정적으로 유지할 수 있습니다.
2. **비용**: 1개월 안에 초기 투자를 회수하고, 5년간 약 6,400만 원을 절감합니다. (※ 가정치 기준)
3. **인터넷 사용**: 인터넷이 끊겨도 작업이 계속되고, 기록만 나중에 전송하면 됩니다.
4. **프라이버시**: 작업 영상이 현장 밖으로 나가지 않습니다.
5. **모델 크기**: ACT 모델이 노트북과 Pi 5에서 돌아갈 수 있는 크기입니다.

클라우드는 "모델이 너무 커서 현장에 둘 수 없을 때" 의미가 있는데, 이 서비스는 그 경우가 아닙니다. 다만 Pi 5의 실제 성능은 **실험 ④ 결과로 최종 확정**해야 하며, Pi 5가 기준(p95 300ms, 성공률 하락 10%p 이내)을 못 맞추면 노트북급 또는 GPU 탑재 엣지 장치로 올리는 것이 클라우드로 가는 것보다 우선 선택지입니다.
