## 1. 작업(Task) 특성

### 1-1. 작업 유형

[v] Pick & Place [ ] 조립/삽입(Peg-in-hole) [ ] 분류/정렬 [ ] 접기/변형체 조작 [ ] 도구 사용 [ ] 기타: \_\_\_\_
→ 왜 필요?: 작업 유형에 따라 중요한 구간(접촉·파지 순간)이 달라져 세그멘테이션 및 샘플 가중치 기준이 결정됨.

### 1-2. 요구 정밀도

[ ] 낮음(±1cm 이상) [ ] 중간(±5mm) [ ] 높음(±1mm 이하)
→ 왜 필요?: 정밀도가 높을수록 액션 스무딩 강도를 낮추고 이미지 해상도/크롭을 보수적으로 설정해야 함.

### 1-3. 작업 단계 수 (Sub-task)

[ ] 단일 동작 [v] 2~3단계 [ ] 4단계 이상 (단계 수: 3 — 집기·이송·놓기)
→ 왜 필요?: 다단계 작업은 단계별 라벨링·분할(Phase segmentation)과 액션 청크 길이 설정에 영향을 줌.

### 1-4. 1회 작업 소요 시간

[ ] 10초 미만 [v] 10~30초 [ ] 30초~1분 [ ] 1분 이상
→ 왜 필요?: 에피소드 길이에 따라 시간 정규화, 다운샘플링 비율, 패딩/절단 방식이 결정됨.

### 1-5. 대상 물체 특성 (복수 선택)

[v] 강체 [ ] 변형체(천·케이블) [ ] 투명 [ ] 반사(금속·광택) [ ] 검정/무광 [ ] 소형(<2cm) [ ] 종류 다양
→ 왜 필요?: 투명·반사 물체는 깊이 결측 보정이 필요하고, 소형 물체는 리사이즈 시 정보 손실을 막기 위한 ROI 크롭이 필요함.

### 1-6. 물체 초기 위치 변동

[ ] 고정 지그 [ ] 소폭 변동(±5cm) [v] 대폭 변동 [ ] 무작위 더미
→ 왜 필요?: 위치 변동 범위가 공간 증강(Random crop/shift) 강도와 데이터 다양성 부족 여부를 판단하는 기준이 됨.

## 2. 작업 환경

### 2-1. 조명 종류

[ ] 고정 LED [ ] 형광등(깜빡임 가능) [ ] 자연광 혼재 [ ] 작업용 국부 조명
→ 왜 필요?: 형광등 플리커와 자연광 변화는 밝기 정규화, 색상 지터 증강, 셔터 속도 보정 필요 여부를 결정함.

### 2-2. 시간대별 조명 변화

[ ] 거의 없음 [ ] 약간 있음 [ ] 심함(창가·주야 교대)
→ 왜 필요?: 조명 변화가 크면 히스토그램 평활화나 Color jitter 증강 범위를 넓혀야 함.

### 2-3. 그림자/글레어

[ ] 없음 [ ] 로봇팔 그림자 있음 [ ] 작업면 반사광 있음 [ ] 둘 다
→ 왜 필요?: 그림자와 글레어는 비전 특징을 오염시키므로 마스킹이나 편광 필터·증강 전략 수립에 필요함.

### 2-4. 배경 복잡도

[ ] 단색/정돈 [ ] 약간 복잡 [ ] 매우 복잡 [ ] 사람/물체가 움직임
→ 왜 필요?: 배경이 복잡하거나 동적이면 배경 마스킹, ROI 크롭, 배경 랜덤화 증강이 필요함.

### 2-5. 작업면 재질/색상

[ ] 무광 단색 [ ] 광택 [ ] 패턴/텍스처 [ ] 물체와 색 유사
→ 왜 필요?: 물체와 배경의 대비가 낮으면 색공간 변환(HSV/LAB)이나 대비 강화 전처리가 필요함.

### 2-6. 진동/외란

[ ] 없음 [ ] 주변 기계 진동 [ ] 카메라 거치대 흔들림 [ ] 작업대 이동 가능
→ 왜 필요?: 진동이 있으면 영상 안정화나 IMU 기반 보정, 관절 데이터 저역통과 필터가 필요함.

### 2-7. 먼지/오염/온도

[ ] 깨끗함 [ ] 먼지 많음 [ ] 유분/수분 [ ] 고온/저온
→ 왜 필요?: 렌즈 오염 가능성이 높으면 이상 프레임 탐지(블러·저대비) 및 노이즈 제거 필터 강도를 조정해야 함.

## 3. 카메라/비전 센서 구성

### 3-1. 카메라 개수 및 위치 (복수 선택)

[v] 고정 상단(Top) [ ] 고정 정면/측면 [v] 손목(Wrist) [ ] 기타: ____ / 총 2대
→ 왜 필요?: 시점별로 크롭·리사이즈·증강 정책이 달라지고, 다중 뷰 정렬 및 결측 뷰 처리 방식이 결정됨.

### 3-2. 센서 종류

[v] RGB만 [ ] RGB-D(스테레오) [ ] RGB-D(ToF/구조광) [ ] 기타: ____ / 모델명: USB UVC 카메라
→ 왜 필요?: 깊이 방식에 따라 결측(Hole) 패턴과 노이즈 특성이 달라 깊이 필터(Spatial/Temporal/Hole-filling) 선택이 바뀜.

### 3-3. 해상도

[v] 640×480 [ ] 1280×720 [ ] 1920×1080 [ ] 기타: \_\_\_\_
→ 왜 필요?: 모델 입력 크기로의 다운스케일 비율과 종횡비 처리(패딩 vs 크롭)를 결정함.

### 3-4. 프레임레이트(FPS)

[ ] 15 [v] 30 [ ] 60 [ ] 카메라별 상이: \_\_\_\_
→ 왜 필요?: 제어 주기와의 비율에 따라 리샘플링·보간 방식과 프레임 정렬 기준이 결정됨.

### 3-5. 노출/화이트밸런스 설정

[ ] 자동 [ ] 수동 고정 [ ] 모름
→ 왜 필요?: 자동 노출은 에피소드 간 밝기 편차를 만들어 색상 정규화나 노출 고정 재수집이 필요할 수 있음.

### 3-6. 셔터 방식

[ ] 글로벌 셔터 [ ] 롤링 셔터 [ ] 모름
→ 왜 필요?: 롤링 셔터는 빠른 동작 시 왜곡이 생겨 손목 카메라 프레임의 블러·왜곡 필터링 기준에 영향을 줌.

### 3-7. 캘리브레이션 상태

[ ] 내부(Intrinsic) 완료 [ ] 외부(Hand-eye/Extrinsic) 완료 [ ] 미실시
→ 왜 필요?: 왜곡 보정(Undistortion)과 깊이-RGB 정합, 3D 포인트클라우드 변환 가능 여부가 결정됨.

### 3-8. 카메라 고정 상태

[v] 견고하게 고정 [ ] 가끔 위치 바뀜 [ ] 세션마다 재설치
→ 왜 필요?: 카메라 위치가 바뀌면 세션 간 시점 차이를 보정하거나 시점 증강을 강화해야 함.

### 3-9. 가림(Occlusion)

[ ] 거의 없음 [ ] 로봇팔이 물체를 가림 [ ] 사람 손/몸이 가림 [ ] 손목캠 근접 시 초점 이탈
→ 왜 필요?: 가림이 잦으면 다중 뷰 융합, 가림 프레임 마스킹, 손목캠 의존도 조정이 필요함.

## 4. 로봇 하드웨어

### 4-1. 로봇팔 종류

[v] 저가형 서보(SO-100/Koch 등) [ ] 협동로봇(UR/Doosan/Franka 등) [ ] 산업용 / 모델명: \_\_\_\_ (SO-101)
→ 왜 필요?: 엔코더 정밀도와 백래시 수준이 달라 관절 데이터 노이즈 필터 강도가 결정됨.

### 4-2. 자유도(DOF)

[ ] 5 [v] 6 [ ] 7 [ ] 양팔(Bimanual) 총 \_\_
→ 왜 필요?: 액션 벡터 차원과 관절별 정규화(Min-max/Z-score) 통계 계산 단위가 결정됨.

### 4-3. 그리퍼 종류

[v] 평행 그리퍼(연속값) [ ] 평행 그리퍼(On/Off) [ ] 흡착 [ ] 다지 핸드
→ 왜 필요?: 그리퍼 값이 이산인지 연속인지에 따라 이진화·스무딩 금지 여부 등 별도 처리 규칙이 필요함.

### 4-4. 기록되는 상태 정보 (복수 선택)

[v] 관절 각도 [ ] 관절 속도 [v] 관절 토크/전류 [ ] 엔드이펙터 포즈 [ ] F/T 센서 [ ] 촉각
→ 왜 필요?: 사용 가능한 관측 모달리티에 따라 정규화 대상, 단위 통일, 멀티모달 동기화 범위가 정해짐.

### 4-5. 액션 표현 방식

[v] 관절 절대 위치 [ ] 관절 델타 [ ] EE 절대 포즈 [ ] EE 델타 [ ] 모름
→ 왜 필요?: 액션 공간에 따라 좌표 변환, 회전 표현(쿼터니언/6D) 변환 및 정규화 방법이 달라짐.

### 4-6. 로봇 제어 주기

[ ] 10Hz [v] 30Hz [ ] 50Hz [ ] 100Hz 이상 [ ] 기타: \_\_\_\_
→ 왜 필요?: 카메라 FPS와의 정렬 기준 및 학습용 리샘플링 주파수 결정에 필요함.

### 4-7. 관찰된 하드웨어 이슈

[ ] 없음 [ ] 관절 떨림(Jitter) [ ] 백래시 [ ] 엔코더 값 튐 [ ] 과열로 토크 저하
→ 왜 필요?: 떨림·튐은 이상치 제거(Median/Hampel 필터)와 저역통과 필터 차단 주파수 설정의 근거가 됨.

## 5. 원격조작(Teleoperation) 방식

### 5-1. 조작 장치

[v] 리더-팔로워 팔 [ ] VR 컨트롤러 [ ] SpaceMouse [ ] 키보드/게임패드 [v] 핸드트래킹 (핸드트래킹은 비교군)
→ 왜 필요?: 장치별로 입력 노이즈와 해상도가 달라 액션 스무딩 및 데드존 처리 방식이 결정됨.

### 5-2. 조작 지연(체감)

[v] 거의 없음 [ ] 약간 있음(~100ms) [ ] 뚜렷함(>200ms)
→ 왜 필요?: 지연이 크면 관측-액션 간 시간 오프셋 보정(Time-shift alignment)이 필요함.

### 5-3. 시연자에게 주는 시각 피드백

[ ] 직접 육안 [ ] 카메라 화면만 [ ] 둘 다
→ 왜 필요?: 카메라 화면만 보고 조작하면 정책 관측과 시연자 정보가 일치해 데이터 품질 해석 기준이 달라짐.

### 5-4. 힘 피드백(Haptic)

[ ] 있음 [v] 없음
→ 왜 필요?: 힘 피드백이 없으면 접촉 구간에서 과도한 힘·진동이 생겨 해당 구간 필터링이 필요할 수 있음.

## 6. 시연(Demonstration) 수집 현황

### 6-1. 시연자 수

[ ] 1명 [ ] 2~3명 [ ] 4명 이상
→ 왜 필요?: 시연자별 스타일 차이(속도·경로)가 크면 시연자 단위 정규화나 다중 모드 처리 전략이 필요함.

### 6-2. 시연자 숙련도

[ ] 초보 [ ] 중간 [ ] 숙련 [ ] 혼재
→ 왜 필요?: 숙련도가 낮거나 혼재하면 품질 점수 기반 에피소드 필터링 기준을 엄격히 해야 함.

### 6-3. 수집 에피소드 수 (현재/목표)

[ ] 20 미만 [v] 20~50 [ ] 50~200 [ ] 200 이상 / 현재 ____ / 목표 50
→ 왜 필요?: 데이터가 적을수록 증강 의존도가 높아지고 필터링으로 버릴 수 있는 여유가 줄어듦.

### 6-4. 성공/실패 비율

[ ] 대부분 성공 [ ] 실패 10~30% [ ] 실패 30% 이상 [ ] 성공 여부 미기록
→ 왜 필요?: 실패 에피소드 제거·라벨링 여부와 성공 판정 자동화 필요성을 결정함.

### 6-5. 시연 중 이상 행동 (복수 선택)

[ ] 시작/끝 정지 구간 김 [ ] 중간 멈칫·망설임 [ ] 재시도(Re-grasp) [ ] 불필요한 우회 경로 [ ] 없음
→ 왜 필요?: 정지 구간 트리밍, 망설임 구간 제거, 재시도 처리 정책 등 궤적 클리닝 규칙의 근거가 됨.

### 6-6. 시연 속도 일관성

[ ] 일정 [ ] 에피소드마다 다름 [ ] 매우 불규칙
→ 왜 필요?: 속도 편차가 크면 시간 정규화(DTW 등)나 속도 기반 이상치 탐지가 필요함.

### 6-7. 환경 리셋 방식

[v] 사람이 수동 리셋 [ ] 지그로 정확히 리셋 [ ] 리셋 없이 연속 수집
→ 왜 필요?: 리셋 장면이 녹화에 섞이는지와 초기 상태 다양성을 판단해 에피소드 경계 처리를 결정함.

### 6-8. 에피소드 메타데이터 기록

[v] 성공여부 [ ] 시연자ID [v] 물체종류/위치 [ ] 특이사항 [ ] 기록 안 함
→ 왜 필요?: 메타데이터가 있어야 조건별 필터링, 분할(train/val) 및 편향 점검이 가능함.

## 7. 동기화 및 타임스탬프

### 7-1. 타임스탬프 기준

[v] 단일 PC 시스템 시계 [ ] 장치별 개별 시계 [ ] 하드웨어 트리거 [ ] 모름
→ 왜 필요?: 시계가 분리되어 있으면 장치 간 시간 오프셋 추정 및 보정 단계가 필수임.

### 7-2. 관찰된 동기화 문제

[ ] 없음 [ ] 프레임 드랍 [ ] 영상-관절 어긋남 [ ] 카메라 간 어긋남 [ ] 타임스탬프 역전/중복
→ 왜 필요?: 드랍 프레임 보간, 최근접 매칭 허용 오차, 비정상 타임스탬프 제거 규칙 설정에 필요함.

### 7-3. 수집 PC 부하

[ ] 여유 있음 [ ] 가끔 렉 [ ] 수집 중 자주 멈춤 / CPU·GPU·저장장치: \_\_\_\_
→ 왜 필요?: 부하로 인한 불규칙 샘플링 여부를 판단해 리샘플링 필요성을 결정함.

## 8. 데이터 저장 형식

### 8-1. 저장 포맷

[ ] ROS bag [ ] HDF5 [v] LeRobot Dataset [ ] 영상(MP4)+CSV [ ] 기타: \_\_\_\_
→ 왜 필요?: 포맷 변환 파이프라인과 프레임 접근 방식(디코딩 비용)을 설계하는 출발점임.

### 8-2. 영상 압축
