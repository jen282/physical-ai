# TeachArm 객체 탐지 모델 학습·검증 설계안 (최종: 축소안 반영)

> 기준: 첫 설계안에 "그래도 탐지기를 유지한다면: 축소안"을 반영한 버전입니다. 탐지기는 노트북에서 녹화 영상을 **사후 일괄 처리**하는 보조 모듈로만 사용합니다.

---

## 0. 탐지기의 역할

**결론**

탐지기는 ACT 제어 루프 밖의 오프라인 보조 모듈입니다. 실험 결과의 공식 판정은 PRD대로 운영자가 합니다.

**내용**

| 용도                | 탐지기 활용 방식                                                                                         |
| ------------------- | -------------------------------------------------------------------------------------------------------- |
| 데이터 QA           | 시연 시작 시 큐브가 보이는지, 증강 후 큐브가 잘리지 않았는지 확인                                        |
| 인식 실패 판정 보조 | 그리퍼 접근 지점(FK)과 탐지된 큐브 중심의 거리(5cm 기준)를 계산해 기록                                   |
| 성공 판정 보조      | 종료 프레임에서 큐브 박스가 **하드코딩된 접시 ROI** 안에 있는지 확인                                     |
| 큐브 위치 기록      | 평가 시도는 그리드 위치 ID를 사용하고, 학습 데이터는 파지 시점 FK 좌표를 사용. 탐지기는 교차 확인에만 씀 |

**이유**

- ACT는 엔드투엔드 정책이라 탐지 결과가 필요하지 않습니다. 정책 입력에 넣으면 "프로그래밍 없는 교시"라는 핵심 가치와 실험 ①~④의 조건이 바뀝니다.
- 탐지기는 실시간일 필요가 없습니다. 그래서 노트북에서 사후 처리하면 Pi 5 이식과 지연 검증 비용이 모두 사라집니다.
- PRD Out of Scope #10(자동 판정 제외)과 충돌하지 않도록, 탐지 결과는 보조 지표로만 기록합니다.

## 1. 모델 선택

### 1.1 모델 크기

**결론**

Nano를 사용합니다.

**내용**

파라미터가 수백만 개 수준인 최소 크기 모델입니다. YOLO26s 승격은 합격선에 미달할 때만 검토합니다.

**이유**

- 장면이 단순합니다. 고정 카메라, 고정 배경에 강체 큐브 1종뿐입니다.
- 유효 장면 수가 50~100개라, 큰 모델은 과적합 위험만 키웁니다.
- 사후 처리라 속도 요구는 없지만, 학습과 반복 실험 시간이 가장 짧습니다.

### 1.2 모델 종류

**결론**

**YOLO26n 단일 모델**을 사용합니다. v8n, 26s와의 비교 실험은 하지 않습니다.

**내용**

COCO 사전학습 가중치 `yolo26n.pt`에서 시작합니다. 합격선에 미달하면 먼저 라벨을 추가하고, 그래도 부족하면 YOLO26s로 승격합니다(2.4의 대체 규칙 참고).

**이유**

- 소형 객체 대응 라벨 할당(STAL)이 있어, 640×480 영상에서 약 30px인 큐브에 유리합니다.
- NMS-free 구조라 후처리 코드가 단순합니다.
- 비교 실험은 공수 대비 기대 이득이 작아 생략합니다.

> YOLO26의 세부 기능과 레이어 구성은 버전마다 달라질 수 있으니, 설치한 `ultralytics` 버전 문서로 확인해 주세요.

### 1.3 모델 도메인

**결론**

Detect 태스크, **`cube` 1개 클래스**, **상단 카메라 전용**으로 구성합니다.

**내용**

- 접시는 탐지하지 않습니다. 테이프 표시 기준으로 접시 ROI 좌표를 설정 파일에 고정합니다.
- 그리퍼 위치는 관절값의 FK로 얻습니다.
- 손목 카메라 영상은 사용하지 않습니다.

**이유**

- 접시는 위치가 고정이라 탐지할 필요가 없고, 클래스가 하나면 라벨링과 검수 비용이 절반 가까이 줄어듭니다.
- Segment는 마스크 라벨 비용이 크고, 위치 판정에는 박스 중심으로 충분합니다.
- 손목 카메라는 큐브의 화면상 크기가 수십 배 달라, 섞으면 단일 모델 성능이 떨어집니다.

## 2. 학습 설계

### 2.1 데이터셋 구축

**결론**

약 **400장**을 자동 박스 생성 + 사람 검수로 만들고, **에피소드 단위**로 분할합니다.

**내용**

| 구성                                                               | 수량                    |
| ------------------------------------------------------------------ | ----------------------- |
| 리더 팔 시연 프레임 (단계별 균등 샘플링: 시작/접근/파지/이송/놓기) | 50 에피소드 × 7장 = 350 |
| 범위 밖 평가 위치 정지 이미지                                      | 20개 위치 × 2장 = 40    |
| 배경 (큐브 없음)                                                   | 10                      |

- **라벨링:** HSV 색상 마스크로 박스를 자동 생성하고, 사람은 검수만 합니다. 가림 프레임처럼 HSV가 실패하는 경우는 파지 시점 FK 좌표를 영상에 투영해 보완합니다.
- **분할:**

| 세트  | 구성                                                             |
| ----- | ---------------------------------------------------------------- |
| train | ACT 학습 에피소드 45개 + 범위 밖·배경 이미지 85%                 |
| val   | ACT 검증 에피소드 5개 + 범위 밖·배경 이미지 15%                  |
| test  | **실험 ①·②의 실제 평가 시도 첫 프레임**. 정답 위치는 그리드 좌표 |

**이유**

- 30fps 영상은 인접 프레임이 거의 같으므로, 많이 뽑아도 정보량은 늘지 않고 과적합만 커집니다.
- 실험 ②의 범위 밖 위치에서 탐지기가 실패하면 그 결과를 쓸 수 없으므로, 범위 밖 이미지는 최소한이라도 포함합니다.
- 라벨링은 이 설계에서 가장 비싼 단계라 자동화 효과가 가장 큽니다.
- 같은 에피소드의 프레임이 train과 val에 섞이면 사실상 같은 이미지로 검증하는 셈이 되어 지표가 부풀려집니다.
- 평가 시도 영상은 어차피 촬영되므로 테스트용 추가 수집이 0입니다. 또 정답 위치가 그리드로 정해져 있어 라벨 없이 위치 오차를 계산할 수 있습니다. 탐지기는 사후 처리이므로 실험 후에 테스트해도 일정에 문제가 없습니다.

### 2.2 fraction, scale, multi_scale 및 증강

**결론**

`fraction`은 0.25(스모크 테스트) → 0.5 → 1.0 순서로 쓰고, `scale=0.2`, `multi_scale=False`로 설정합니다.

**내용**

| 파라미터                  | 설정                                           | 이유                                                                                        |
| ------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `fraction`                | 0.25로 1회 스모크 테스트 → 0.5 / 1.0 학습 곡선 | 0.25로 파이프라인 버그를 수 분 안에 확인. 0.5와 1.0의 결과가 비슷하면 라벨을 더 늘리지 않음 |
| `imgsz`, `rect`           | 640, True                                      | 소형 큐브의 해상도를 보존. 4:3 원본의 패딩 낭비를 줄임. ACT용 320×240과는 분리              |
| `multi_scale`             | False                                          | 카메라와 해상도가 고정이라 연산만 늘어남                                                    |
| `scale`                   | 0.2 (기본값 0.5에서 낮춤)                      | 상단 카메라에서 큐브 크기가 거의 일정함. 0.5면 비현실적으로 작은 큐브가 생성됨              |
| `translate` / `degrees`   | 0.1 / 0                                        | 위치 다양성은 보강하되, 고정 카메라라 회전은 발생하지 않음                                  |
| `fliplr`                  | 0.5                                            | 탐지 라벨은 영상과 함께 반전되므로 ACT와 달리 안전함                                        |
| `mosaic` / `close_mosaic` | 0.5 / 15                                       | 모자이크는 객체를 축소하므로 비율을 낮추고, 마지막 15에포크는 실제 장면으로 마무리          |
| `mixup`                   | 0                                              | 단일 물체 장면에는 불필요                                                                   |
| `hsv_h/s/v`               | 0.015 / 0.5 / 0.3                              | 전처리 단계 7의 ColorJitter와 강도를 맞춤                                                   |

**이유**

`fraction` 학습 곡선은 "라벨을 더 달면 성능이 오르는가"를 판단하는 가장 싼 방법입니다. 축소안의 핵심인 라벨 수 절감이 타당한지 이 곡선으로 확인합니다. 나머지 증강은 고정 카메라, 고정 크기라는 데이터 특성에 맞춰 기본값보다 약하게 설정합니다.

### 2.3 에포크와 patience

**결론**

`epochs=80`, `patience=20`으로 설정합니다.

**내용**

val mAP50-95가 20에포크 동안 개선되지 않으면 조기 종료하고, `best.pt`를 사용합니다.

**이유**

- 이미지가 약 400장이라 수렴이 빠릅니다. T4 기준 학습 시간은 15~20분 수준입니다.
- patience가 너무 짧으면 소형 객체의 위치 정밀도(mAP50-95)가 늦게 오르는 구간을 놓칩니다.

### 2.4 파인튜닝 전략: 단일 단계 vs 2단계, freeze

**결론**

**단일 단계 전체 파인튜닝**(`freeze=0`)을 사용합니다.

**내용**

- COCO 사전학습 가중치에서 시작해 전체 레이어를 한 번에 학습합니다.
- **대체 규칙 1:** 학습 초반 10에포크 안에 val mAP가 떨어지기 시작하면(과적합 신호), `freeze=10`으로 백본을 고정하고 다시 학습합니다. 고정할 레이어 수는 `model.info()`로 백본 경계를 확인한 뒤 맞춥니다.
- **대체 규칙 2:** 합격선에 미달하면, `fraction` 곡선이 아직 상승 중일 때는 라벨을 추가하고, 평탄할 때는 YOLO26s로 승격합니다.

**이유**

- Nano 모델과 단순 장면에서는 2단계 학습의 이득이 작고, 이를 확인하려면 대조 실험이 필요합니다. 그 실험은 축소안에서 제외했습니다.
- 과적합 위험은 낮은 학습률, weight decay, early stopping으로 충분히 통제됩니다.
- 학습 절차가 한 번으로 끝나 README 재현성(PRD KPI)이 단순해집니다.

### 2.5 Optimizer

**결론**

**AdamW**로 고정합니다.

**내용**

`optimizer="AdamW"`로 명시하고, `weight_decay=5e-4`를 적용합니다. MuSGD 등 다른 optimizer와의 비교는 하지 않습니다.

**이유**

- 반복 횟수가 1만 회 미만인 소량 파인튜닝에서는 AdamW가 안정적으로 수렴합니다.
- `auto`도 이 조건에서 AdamW를 고르지만, 버전마다 선택 로직이 달라질 수 있어 재현성을 위해 명시합니다.

### 2.6 학습률, lrf, warmup_epochs

**결론**

`lr0=1e-3`, `lrf=0.01`, `warmup_epochs=3`, `cos_lr=True`로 설정합니다.

**내용**

학습률은 3에포크 동안 워밍업으로 올라간 뒤, 코사인 곡선을 따라 최종값 1e-5(= 1e-3 × 0.01)까지 감소합니다.

**이유**

- SGD 기본값 0.01은 AdamW에 비해 지나치게 커서 사전학습 가중치를 훼손합니다. 1e-3이 적정 수준입니다.
- 후반의 낮은 학습률이 박스 위치를 미세 조정해 위치 오차를 줄입니다.
- 워밍업은 새로 초기화된 Head가 초반에 큰 그래디언트로 백본을 흔드는 것을 막습니다. 3에포크면 80에포크 중 짧은 비중으로 충분합니다.

### 2.7 하드웨어 리소스 최적화

**결론**

Colab 무료 T4 1장에서 **AMP + RAM 캐시**로 학습하고, 분산 학습은 사용하지 않습니다.

**내용**

| 항목      | 설정                                  | 이유                                                                   |
| --------- | ------------------------------------- | ---------------------------------------------------------------------- |
| AMP       | `amp=True`                            | T4의 FP16 텐서코어로 속도 약 1.5~2배, 메모리 절감                      |
| 캐싱      | `cache='ram'`                         | 400장 × 640px는 1GB 미만이라 RAM에 충분히 들어감. 디스크 I/O 병목 제거 |
| batch     | `batch=-1` (자동)                     | GPU 메모리에 맞춰 자동 설정                                            |
| workers   | 2                                     | Colab vCPU 수에 맞춤                                                   |
| 분산 학습 | 사용하지 않음                         | 20분이면 끝나는 규모라 DDP 설정 비용이 이득보다 큼                     |
| 저장      | 체크포인트는 Google Drive, 로그는 W&B | Colab 세션 끊김 대비, ACT와 같은 실험 추적 체계                        |
| 배포      | `.pt` 그대로 노트북에서 사용          | 사후 처리라 ONNX/NCNN 변환이 불필요                                    |

**이유**

이 규모에서는 GPU 비용보다 사람 시간이 훨씬 비쌉니다. 설정 한 줄로 얻는 최적화(AMP, 캐시)만 적용하고, 설정 비용이 드는 것(분산 학습, 엣지 변환)은 제외합니다.

### 2.8 학습 코드

```python
from ultralytics import YOLO

model = YOLO("yolo26n.pt")
model.train(
    data="teacharm_cube.yaml",          # nc: 1, names: [cube]
    imgsz=640, rect=True, multi_scale=False,
    scale=0.2, translate=0.1, degrees=0, fliplr=0.5,
    mosaic=0.5, close_mosaic=15, mixup=0,
    hsv_h=0.015, hsv_s=0.5, hsv_v=0.3,
    epochs=80, patience=20, freeze=0,
    optimizer="AdamW", lr0=1e-3, lrf=0.01, cos_lr=True,
    warmup_epochs=3, weight_decay=5e-4,
    amp=True, cache="ram", batch=-1, workers=2,
    fraction=1.0,                       # 스모크 테스트 0.25 → 곡선 0.5 / 1.0
    seed=42, deterministic=True,
    project="/content/drive/MyDrive/teacharm/det", name="cube_n",
)
```

## 3. 검증 설계

### 3.1 confidence 설정

**결론**

mAP 계산용(`conf=0.001`)과 운영용(val F1 최대 지점)을 분리합니다. 운영 시에는 **큐브 최고 점수 박스 1개만 채택**합니다.

**내용**

| 용도                        | conf                            | 처리                                               |
| --------------------------- | ------------------------------- | -------------------------------------------------- |
| mAP 계산                    | 0.001 (기본값)                  | PR 곡선 전체를 계산                                |
| 위치 기록                   | val F1 최대 지점 (예상 0.4~0.6) | 임계값 이상인 박스 중 최고 점수 1개                |
| 데이터 QA (큐브가 보이는가) | 0.25                            | recall 우선                                        |
| 인식 실패·성공 판정 보조    | 0.6                             | 미달이면 "판정 보류"로 표시하고 운영자 판정만 사용 |

**이유**

- mAP 계산 시 conf를 높이면 PR 곡선이 잘려 AP가 왜곡됩니다.
- 장면에 큐브는 정확히 1개이므로, 최고 점수 1개 규칙만으로 오탐이 구조적으로 거의 사라집니다.
- 용도마다 실수 비용이 다릅니다. QA에서는 놓치는 것이 더 나쁘고, 판정 보조에서는 잘못 판정하는 것이 더 나쁩니다.
- YOLO26은 NMS-free라 NMS IoU 임계값은 조정 대상이 아닙니다.

### 3.2 평가 지표

**결론**

합격 판정에는 **중심 위치 오차(cm) p95**와 **Recall** 두 개만 사용합니다. mAP50-95, mAP50, Precision은 참고용으로만 기록합니다.

**내용**

- **중심 위치 오차:** 테이프 표시 4점으로 호모그래피를 구하고, 박스 하단 중심을 책상 좌표(cm)로 변환합니다. 이 값을 테스트 프레임의 그리드 정답 좌표와 비교합니다.
- **Recall:** 운영 conf에서 큐브를 찾은 비율입니다.
- **참고 지표:** mAP50-95, mAP50, Precision은 학습 시 자동으로 출력되므로 W&B에 기록만 합니다.

**이유**

- 탐지기의 출력은 박스가 아니라 "책상 위 큐브 좌표"로 쓰입니다. 인식 실패 판정(5cm 기준)과 접시 ROI 판정 모두 이 좌표를 직접 사용하므로, 위치 오차가 실제 용도와 가장 직결된 지표입니다.
- 큐브를 놓치면 그 시도의 보조 판정이 통째로 사라지므로 Recall이 두 번째 핵심입니다.
- mAP50은 단순 장면에서 거의 포화되어 변별력이 낮습니다. Precision은 최고 점수 1개 규칙으로 구조적으로 높아집니다. mAP50-95는 위치 오차의 간접 지표일 뿐이라, 직접 지표가 있으면 합격 기준으로 둘 필요가 없습니다.

### 3.3 평가 지표 임계값

**결론**

**위치 오차 p95 ≤ 1.5cm**, **Recall ≥ 0.95**를 합격선으로 합니다. 범위 안과 범위 밖에 같은 기준을 적용합니다.

**내용**

| 지표               | 합격선  | 미달 시 조치                                                             |
| ------------------ | ------- | ------------------------------------------------------------------------ |
| 중심 위치 오차 p95 | ≤ 1.5cm | 2.4의 대체 규칙 2 적용 (라벨 추가 또는 YOLO26s 승격)                     |
| Recall (운영 conf) | ≥ 0.95  | 놓친 프레임의 공통점(위치, 가림, 밝기)을 확인한 뒤 해당 조건 이미지 추가 |

오차가 큰 프레임은 작업 영역 산점도에 겹쳐 그려, 특정 구역(영역 모서리, 범위 밖)에 몰리는지 확인합니다.

**이유**

- 인식 실패 기준이 5cm이므로, 1.5cm 오차는 3배 이상의 여유가 있어 판정 오류를 무시할 수 있는 수준입니다. 그리드 간격(약 4~5cm) 안에서 위치도 구분됩니다.
- 고정 카메라에 정지 큐브라는 조건에서 Recall 0.95는 무리 없이 달성할 수 있는 수준입니다. 동시에 시도 20회 중 놓치는 경우가 1회 이하라 보조 판정이 쓸모 있습니다.
- 범위 밖 기준을 따로 두지 않는 것은 지표를 줄이는 축소안의 원칙 때문입니다. 범위 밖에서만 미달하면 범위 밖 이미지를 우선 추가합니다.
