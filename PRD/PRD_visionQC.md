## 1. 문제 정의 (Problem Statement)

### 1.1 현재 존재하는 문제

- 공장 라인에는 부품이 초당 10개씩 지나갑니다. 사람이 하나하나 눈으로 보고 걸러내기에는 너무 빠릅니다.
- 육안 검사는 피로가 누적되면 정확도가 떨어집니다. 야간·장시간 근무에서 작은 흠집을 놓치면 불량품이 그대로 출하됩니다. (가정: 육안 검사 불량 검출률 85~90%)
- 불량이 고객에게 넘어가면 클레임, 반품, 재작업 비용이 발생하고 거래처 신뢰가 떨어집니다.

### 1.2 기존 방식의 한계

| 방식 | 한계 |
| --- | --- |
| 육안 검사 | 속도 한계, 검사원마다 기준이 다름, 야간 정확도 하락, 24시간 인력 운영 비용 |
| 규칙 기반 비전 검사 (임계값·패턴 매칭) | 조명·표면 질감이 조금만 달라져도 오검출이 늘고, 신제품마다 규칙을 사람이 다시 짜야 함 |
| 클라우드 AI 검사 | 판정 50ms를 매번 보장하기 어렵고, 외부 인터넷이 막힌 공장에서는 구성 불가. 하루 2TB 업로드 비용과 영업비밀 유출 위험이 큼 |

### 1.3 해결하려는 핵심 가치

1. **전수 검사**: 샘플링이 아니라 지나가는 모든 부품을 50ms 안에 판정합니다.
2. **일정한 품질**: 24시간 같은 기준으로 판정합니다.
3. **영업비밀 보호**: 신제품 설계가 담긴 영상이 공장 밖으로 나가지 않습니다.
4. **즉시 조치**: 판정과 동시에 배출기를 구동해 불량품이 다음 공정으로 넘어가지 않게 합니다.

### 1.4 왜 AI가 필요한가

- 흠집·변형은 크기, 위치, 방향, 명암이 매번 다릅니다. 규칙으로 모든 경우를 정의할 수 없지만, 딥러닝 모델은 정상·불량 영상 예시에서 패턴을 학습합니다.
- 신규 불량 유형이 나오면 코드를 고치는 대신 영상을 추가해 **재학습**하면 됩니다.
- 불량 데이터가 매우 적은 초기에는 정상 영상만으로 학습하는 이상 탐지(anomaly detection) 방식을 함께 사용해 미지의 불량도 잡아냅니다.

## 2. 사용자 시나리오 (User Scenario)

**주요 사용자**: 품질관리(QC) 담당자, 라인 작업자, 설비 보전 담당자 (가정)

| 단계 | 내용 |
| --- | --- |
| **1. 설치** | 설비 담당자가 컨베이어 위에 카메라 4대와 LED 조명을 고정하고, 라인 옆에 산업용 GPU PC를 설치한다. 부품 감지 센서·엔코더·배출기를 PC의 I/O에 연결한다. QC 담당자는 관리자 페이지에서 정상 부품 샘플 촬영과 검사 기준(불량 판정 민감도)을 등록한다. |
| **2. 데이터 수집** | 부품 감지 센서가 신호를 보내면 카메라가 정확한 순간에 촬영한다 (스트로브 조명 동기). 영상은 GigE 케이블로 GPU PC에 전달된다. 40대 카메라 전체에서 하루 약 2TB가 생성되며, **공장 내부망 밖으로 나가지 않는다.** |
| **3. 분석** | GPU PC가 영상을 전처리한 뒤 불량 탐지 모델(약 100MB)로 추론한다. 부품의 정상/불량 여부, 불량 종류(흠집·변형 등), 불량 위치를 계산한다. |
| **4. 판단 결과 생성** | 불량 점수가 임계값을 넘으면 `NG`, 아니면 `OK`로 판정한다. 판정 결과, 불량 이미지, 신뢰도, 시각(타임스탬프)을 한 건의 기록으로 만든다. 촬영부터 판정까지 **50ms 이내**에 끝낸다. |
| **5. 제어** | `NG` 판정 시 엔코더 위치 기준으로 해당 부품이 배출기 앞에 도착하는 순간 PLC에 신호를 보내 에어 블로워/푸셔를 작동시킨다. 부품은 불량 상자로 떨어진다. 연속 불량이 기준 횟수를 넘으면 경광등을 켜고 담당자에게 알림을 보낸다. |
| **6. 확인 및 후속 조치** | QC 담당자가 대시보드에서 불량률 추이와 불량 이미지를 확인한다. 불량이 급증하면 앞 공정(금형, 가공 장비)을 점검한다. 오판정(정상인데 불량 처리, 불량인데 통과)은 관리자 페이지에서 정정 표시하고, 이 데이터가 다음 재학습에 사용된다. |

## 4. 기술 스택 (Technology Stack)

| 구성 | 사용 기술 | 선정 이유 |
| --- | --- | --- |
| 카메라 | 산업용 5MP 에리어스캔 카메라, GigE Vision (PoE) (가정: Basler ace 2급) | 산업용 표준 인터페이스, 하나의 케이블로 전원·데이터 공급, 글로벌 셔터로 움직이는 부품 촬영 가능 |
| 조명 | LED 바 조명 + 스트로브 컨트롤러 | 흠집은 조명 각도에 따라 보이므로 일정한 조명이 정확도를 좌우함 |
| 센서 | 광전 센서(부품 감지), 로터리 엔코더(벨트 위치) | 정확한 촬영 시점과 배출 시점 계산에 필요 |
| MCU / 제어기 | PLC (Modbus TCP / OPC UA 지원) + 트리거 보드 (가정: STM32 기반) | 공장 설비에서 가장 널리 쓰는 제어기, 카메라·조명 트리거를 μs 단위로 동기 |
| 엣지 AI 장비 | 산업용 GPU PC (NVIDIA GPU 탑재, 팬리스/방진형) × 10 | 주어진 사양. 현장 설치 가능, 카메라 4대 동시 처리 |
| 추론 엔진 | NVIDIA TensorRT (FP16) | 같은 GPU에서 추론 시간을 크게 줄이는 사실상 표준 도구 |
| AI 모델 | 불량 분류·위치 탐지 모델(YOLO 계열 경량 모델) + 이상 탐지 모델(PatchCore 계열), 약 100MB (가정) | 지도학습은 알려진 불량을, 이상 탐지는 처음 보는 불량을 담당 |
| 학습 환경 | 사내 GPU 워크스테이션 + PyTorch (사내망 내) | 영상이 외부로 나가지 않도록 학습도 사내에서 수행 |
| 서버 | 사내 온프레미스 서버 1대 (Linux, Docker) | 10대 PC의 데이터 취합, 모델 일괄 배포, 대시보드 운영 |
| 통신 | 카메라↔PC: GigE / PC↔PLC: Modbus TCP·OPC UA / PC↔서버: MQTT, HTTPS (사내망) | 공장 표준 프로토콜, 가벼운 메시지(MQTT)로 판정 결과 전송 |
| 데이터베이스 | PostgreSQL(판정 이력·로그) + MinIO(불량 이미지 저장) | 이력은 관계형 DB, 대용량 이미지는 오브젝트 스토리지로 분리 |
| 대시보드 | Grafana + 관리자 웹(React, FastAPI) | 불량률 추이는 Grafana, 기준 설정·정정 기능은 관리자 웹 |
| 알림 시스템 | 경광등(PLC 출력) + 사내 메신저/SMS 게이트웨이 | 현장에는 즉각적인 경고, 담당자에게는 원격 알림 |
| 배포·운영 | Docker, 사내 레지스트리, 모델 버전 관리 | 10대에 같은 모델을 일괄 배포하고 문제 시 롤백 |

### 6.6 참고: 클라우드 방식과의 비용 비교

주어진 자료 기준 클라우드 방식은 연 운영비가 4.1억 원(월 약 3,417만 원)입니다. 절감 효과가 같다고 가정하면 월 순 절감액은 약 7,583만 원(110,000,000 − 34,170,000)으로, 엣지(약 1억 333만 원)보다 낮습니다. 5년 누적 비용도 엣지 2.2억 원 대비 20.5억 원입니다. 다만 이 계산은 클라우드의 50ms 지연 보장과 외부 인터넷 제한 문제를 해결할 수 있다고 가정한 것이며, 실제로는 이 두 조건 때문에 구성 자체가 어렵습니다. 상세 비교는 `report/report.md`를 참고합니다.
